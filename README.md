# EE5110/EE6110 Segment B CA：事件相机模拟器

本仓库是 EE5110/EE6110 Segment B 持续性考核（Continuous Assessment，CA）
项目 **“Design an Event Data Simulator”** 的 Python 实现。程序将普通视频转换为
按时间排序的事件流，并生成一段将模拟事件叠加在输入画面上的演示视频。

本实现以 `EE5110_6110_JiangRui_Lec01.pdf` 中提出的要求为目标，主要参考
第 4、6、11-14 和 92-96 页。该课件由课程方通过 Canvas 提供，不随源码仓库
分发；本文页码基于 2026 年 8 月 10 日的课件版本。

## 项目状态

通过代码检查可以确认，核心模拟流程已经覆盖单像素模型、事件列表输出、流式存储
和可视化。项目已在 Python 3.12.14 环境中完整处理 1000 FPS 火焰、960 FPS
机械齿轮和 240 FPS 降雪三段高速序列。推荐的齿轮序列为 640 x 360、506 帧，默认参数生成

极性、快照和叠加视频均通过检查。生成结果保存在本地 `output/`
中，但该目录由 Git 忽略。本项目仍然不能视为已经完成 CA：还需要自动化正确性
测试、多 FPS 和多阈值对照实验，以及代码之外的提交材料。

如果需要输入视频本身超过 5 秒，可以使用 640 x 360、240 FPS、1295 帧的降雪

## 事件模型

对于每一帧输入图像，模拟器首先将灰度数字量 `D_k(x, y)` 转换为对数亮度：

```text
L_k(x, y) = log(D_k(x, y) / 255 + epsilon)
```

每个像素维护一个参考对数亮度 `R(x, y)`。读取第一帧时，程序使用该帧的
`L_0(x, y)` 初始化参考亮度和前一帧亮度，第一帧本身不生成事件。从第二帧开始，
当亮度相对参考值的增量跨越正阈值 `C_pos` 时生成正事件；当亮度下降量跨越负阈值
`C_neg` 时生成负事件：

```text
n_pos = floor(max(L_k - R, 0) / C_pos)
n_neg = floor(max(R - L_k, 0) / C_neg)
```

如果同一个像素在两帧之间跨越多个阈值，模拟器会为每次阈值穿越分别生成事件。
对于第 `j = 1, ..., n` 级穿越，正事件的目标亮度为
`L_target = R + j * C_pos`，负事件的目标亮度为
`L_target = R - j * C_neg`。连续事件时间通过线性插值估计：

```text
alpha = (L_target - L_(k-1)) / (L_k - L_(k-1))
t_event = t_(k-1) + clip(alpha, 0, 1) * (t_k - t_(k-1))
```

程序先按照连续时间进行稳定排序，再将事件时间量化到配置的时间戳分辨率。
输出时间戳保证非递减；如果多个事件在量化后具有相同时间戳，则保留它们在量化前
经过连续时间排序后在输出数组中的相对顺序。时间戳分辨率不等同于时间戳精度：
时间估计仍受输入帧率、
`frame_index / FPS` 的帧时间计算方式，以及线性插值假设限制。参考亮度根据已经
跨越的阈值更新：

```text
R <- R + n_pos * C_pos - n_neg * C_neg
```

当前模型有意省略阈值不匹配、散粒噪声、热像素、不应期（refractory period）、
读出延迟、漏事件和带宽限制。在讨论模拟真实性时，必须明确说明这些简化。

## 处理流程

```text
输入视频
    |
    v
读取视频帧，并通过 帧序号 / FPS 计算时间戳
    |
    v
将灰度数字量转换为对数亮度
    |
    v
生成阈值穿越事件并按时间排序
    |--------------------|----------------------|
    v                    v                      v
追加写入 HDF5       收集 CSV 样例       更新事件快照和叠加视频
    |                    |                      |
    +--------------------+----------------------+
                         |
                         v
                  校验并完成输出
```

处理流程每次只处理一帧。完整的历史事件会立即增量写入磁盘，而不是一直保留在
内存中。因此，内存占用主要取决于当前视频帧、当前事件批次和可视化时间窗口。
这一点非常重要，因为普通视频中的一个像素在相邻两帧之间可能生成多个事件。

## 运行模拟器

将 `.mp4`、`.avi`、`.mov` 或 `.mkv` 文件直接放入 `input/`，然后运行下面的
命令。实际支持的容器和编码格式取决于当前 OpenCV 安装中可用的编解码器。

```bash
python -m event_camera_sim run --video snowfall_240fps_640x360.mp4
```

也可以通过交互菜单选择可用视频：

```bash
python -m event_camera_sim run
```

仓库中的 `demo.mp4` 为 1920 x 1080、30 FPS、时长 41 秒。它适合作为压力测试，
但不足以作为有说服力的高帧率 CA 演示。120 FPS 告警阈值是本项目自行选择的参数，
不是课件规定的最低要求；课件中的 960 FPS 也只是一个示例。

`fire_1000fps_320x80.mp4` 来自 Mark Kilby 使用 Casio Exilim HS 高速相机以
1000 FPS 实际拍摄的火焰序列。公开源文件以 30 FPS 慢放，项目版本完整保留全部
963 个互不重复的采集帧，将时间基准恢复为 1000 FPS，并将空间分辨率从
640 x 160 缩小到 320 x 80；没有创建、复制或插值时间帧。详细来源、修改说明和
CC BY-SA 3.0 许可见 `input/fire_1000fps_320x80.source.txt`。

更推荐 `clock_gear_960fps_640x360.mp4` 作为演示素材。它是以 960 FPS 拍摄的
钟表驱动齿轮，背景稳定、运动区域集中，因而比整幅持续变化的火焰更容易同时观察
原场景和事件。项目版本保留全部 506 个连续采集帧，将公开文件的 30 FPS 慢放时间
基准恢复为 960 FPS，并从 1280 x 720 缩小到 640 x 360；没有创建、复制或插值
时间帧。来源采用 CC0 许可，详情见 `input/clock_gear_960fps_640x360.source.txt`。

仿真时间轴和展示时间轴有意分离。事件生成使用输入视频的 960 FPS，即相邻帧相差
约 1.042 毫秒；`event_overlay.mp4` 保留相同的 506 帧，但以 30 FPS 输出，因此播放
时长为 16.87 秒。这只是慢放展示，不会修改 HDF5 中的事件时间戳。

`snowfall_240fps_640x360.mp4` 是实际速度保存的 240 FPS 降雪序列，不需要恢复
时间基准。项目版本保留全部 1295 帧，将 1280 x 720 缩小到 640 x 360，并移除
音轨；输入物理时长为 5.396 秒。详细来源、修改说明和 CC BY 3.0 许可见
`input/snowfall_240fps_640x360.source.txt`。

简单复制或插值 30 FPS 视频帧不会增加真实采集的时间信息，不应当作为高帧率实验
依据。事件输出可能远大于压缩后的输入视频，因此在处理高分辨率或长视频前应先
检查可用磁盘空间。

## 参数配置

当前需要在 `src/event_camera_sim/config.py` 中修改模拟参数：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `CONTRAST_THRESHOLD_POS` | `0.4` | 正对数亮度阈值 |
| `CONTRAST_THRESHOLD_NEG` | `0.4` | 负对数亮度阈值 |
| `EPSILON` | `1e-3` | 避免计算 `log(0)` |

| `SNAPSHOT_START_TIME` | `0.3 s` | 静态事件快照窗口的开始时间 |
| `SNAPSHOT_DURATION` | `0.005 s` | 静态事件快照窗口的持续时间 |
| `OVERLAY_PLAYBACK_FPS` | `30 FPS` | 叠加视频的慢放帧率，不影响仿真时间戳 |
| `OVERLAY_EVENT_ALPHA` | `0.45` | 叠加事件的不透明度，保留原画面可见性 |
| `EVENT_CSV_MAX_EVENTS` | `100000` | 可读 CSV 样例的最大事件数 |
| `HDF5_CHUNK_EVENTS` | `262144` | HDF5 追加写入和压缩的分块大小 |

## 生成结果

结果按照输入视频的文件名主干和参数值组织：

```text
output/<video>/<parameter-tag>/
|-- events.h5
|-- events_sample.csv
|-- event_snapshot.png
|-- event_overlay.mp4
`-- metadata.json
```

使用默认配置处理推荐齿轮素材时，输出目录为：

```text
output/clock_gear_960fps_640x360/pos0.4_neg0.4_eps0.001_ts1e-06_acc0.002_snap0.3-0.005_view30_alpha0.45/
```

参数标签的格式为：
`pos<正阈值>_neg<负阈值>_eps<epsilon>_ts<时间戳分辨率>_acc<累积时间>_snap<开始时间>-<持续时间>_view<展示FPS>_alpha<事件不透明度>`。

`events.h5` 是完整事件列表的权威输出，其中包含四个一维数据集：

| 数据集 | 类型 | 含义 |
| --- | --- | --- |
| `/x` | `int32` | 像素列坐标 |
| `/y` | `int32` | 像素行坐标 |
| `/t` | `float64` | 以秒为单位的时间戳 |
| `/p` | `int8` | 极性：`+1` 表示 ON，`-1` 表示 OFF |

默认情况下，`events_sample.csv` 只包含最前面的 100,000 个事件，不能将它当作
完整结果。`metadata.json` 会记录输入属性、模型假设、参数、事件数量、告警、输出
文件信息和各处理阶段耗时。

程序首先写入 `events.partial.h5`、`events_sample.partial.csv`、
`event_snapshot.partial.png`、`event_overlay.partial.mp4` 和
`metadata.partial.json`。只有当程序内置的字段长度、事件数量和完成状态检查通过后，
才会替换为正式文件名。写入器还会拒绝时间戳递减的事件。这些运行时保护已经存在于
代码中，但目前尚无自动化测试覆盖。使用相同参数重复处理同一个视频时，对应的最终
输出文件会被替换，不会自动创建新的运行编号。

## 提交前需要完成的验证

仓库目前没有自动化测试，也没有整理完成的可复现实验报告。虽然 960 FPS 和 1000 FPS
端到端运行已经通过人工和程序化检查，但在将模拟器视为 CA 完成版本前，仍应补充
以下验证：

1. **单像素测试：**验证未达到阈值时无事件、单次阈值穿越、多次阈值穿越、正负
   极性、参考值更新、插值时间和时间戳量化。
2. **存储测试：**验证 HDF5 字段长度一致、时间戳单调、元数据属性、分块读取和
   运行中断时的处理。
3. **可视化测试：**验证 ON/OFF 颜色、事件累积窗口、快照时间、视频帧数和输出
   分辨率。
4. **多 FPS 实验：**使用不同帧率处理等效运动，并讨论事件数量和时间戳差异。
5. **阈值实验：**比较不同正负阈值，并解释阈值对事件密度的影响。
6. **性能测量：**记录运行时间、事件吞吐量、峰值内存、输出大小，以及事件生成、
   存储和可视化分别占用的时间。
7. **定性检查：**在展示中加入有代表性的输入帧、事件快照和叠加视频帧。

## 已知差距与建议优先级

### 优先级 1：补充 CA 所需证据

- 使用另一段高速场景复核结果，并基于同一原始高速素材设计多 FPS 对照实验。
- 为数学模型和输出不变量添加可重复运行的测试。
- 保留有代表性的输出，或者提供脚本和小型测试数据，使评阅者可以快速复现结果。
- 提供定量实验结果和讨论，而不是只描述实现设计。

### 优先级 2：改善易用性和实验控制

- 将正负阈值、时间戳分辨率、累积时间、快照窗口和输出目录暴露为 CLI 参数。
- 添加环境锁文件或 `environment.yml`，实现精确环境复现。
- 增加限制处理帧数或快速运行的选项，避免评阅者必须处理完整的 41 秒全高清视频。
- 提前报告预计磁盘需求，或者支持仅生成可视化而不保留完整事件流。
- 在元数据和输出命名中加入输入来源标识、代码版本或运行编号。当前路径会在不同
  输入具有相同文件名主干时发生冲突，使用相同参数重复运行也会覆盖之前的结果。

### 优先级 3：提高模型真实性或说明简化理由

- 决定是否模拟像素扫描或仲裁机制；如果不模拟，应明确说明选择独立像素处理的
  理由。
- 如果需要支持可变帧率视频，应使用视频实际的显示时间戳；当前读取器假设
  `timestamp = frame_index / FPS`。
- 说明 OpenCV 灰度数字量不等同于经过标定的物理照度，并说明当前模型假设相邻帧
  之间的对数亮度呈线性变化。
- 如果时间允许，可以增加可配置的传感器效应，例如阈值不匹配、不应期、漏电流
  引起的背景事件、热像素或噪声。这些属于扩展功能，不能替代对理想模型的验证。
